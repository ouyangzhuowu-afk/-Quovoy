# 独立业务风险检查清单

这是一份验收设计，不是测试通过记录。实际结果、命令、版本和证据写入 [ACCEPTANCE.md](ACCEPTANCE.md)。每项结论使用“已验证／未验证／失败／不适用并说明理由”，不能仅因实现了函数或生成了截图就勾选。

## 交付证据核对

- README 可按实际命令启动；锁文件、`.env.example`、实际可用演示入口齐全。
- 至少 10 组合成询价各有用途；可提取样本有人工期望值和来源，不用生产提取器生成“真值”。
- 类型检查、构建和适用测试记录实际命令、时间、退出码与覆盖边界。
- 真实模型无 Key 时明确“未验证”，连接代码不是调用成功证据；浏览器无法运行时明确该项缺失。
- 当前代码、正式导出内容、文档限制和验收结论一致。发现未通过项时列影响范围与具体下一动作。
- 试点模板没有合成“成功率”；真实效率／付款／生产部署另设状态和证据。

## 完成与风险接受

本地技术 MVP 的必做项必须由实际检查支持。跨组织访问、失控审批、错误金额、旧批准沿用、未批准正式导出、自动外发、原件静默丢失或持久化丢失属于核心阻塞，不能用“演示环境”解释为通过。

无模型凭据、无客户真实资料、无邮箱／生产账号属于外部验证限制：完成不依赖这些条件的实现和检查，单独列为待外部验证。OCR、ERP 等明确排除项不构成当前阻塞。风险接受必须写明风险、受影响范围、临时控制、负责人和验证期限；未得到授权不能把本地演示推广为可公开上线。
