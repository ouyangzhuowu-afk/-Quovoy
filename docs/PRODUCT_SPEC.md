# Quovoy 产品规格

版本：本地技术 MVP，2026-10-02。本文约定产品行为；实际实现、运行命令、通过和未通过的检查以 [ACCEPTANCE.md](ACCEPTANCE.md) 为准。规格存在不代表验收通过。

## 使用对象与范围

服务 20–100 人、每月约 30–300 份询价的工业零部件出口商、贸易商和合同制造商。首个品类限定为机械零部件／金属加工件，整理邮件、文本 PDF 和 Excel 中明确写出的要求。工程图中的尺寸、公差、工艺和可制造性由人确认。

核心流程为：导入询价 → 拆分产品行 → 对照来源修正和确认 → 处理缺失与冲突 → 人工录入成本及条款 → 确定性计算 → 主管审批确定版本 → 导出获批报价 → 人工确认已发送 → 跟进。

本次交付技术流程、合成样本、测试证据与试点材料。真实模型质量、50% 人工耗时下降、90% 关键字段准确率和一个付费客户均为待验证目标。演示数据不计入商业结果。

不包含自动外发、自动谈价、交付承诺、实时汇率、自动税费、供应商自动选择、完整 CRM、OCR、CAD 理解、ERP 双向写入、计费和邮箱收件连接。

## 页面与角色

桌面优先、中文工作界面、英文可复制外发草稿。主要工作区可以合并，但以下动作必须可见：

| 工作区 | 需要完成的动作 |
| --- | --- |
| 收件箱 | 导入、查看客户／时间／负责人／状态／问题数、识别合成样本和重复导入 |
| 审核 | 并排阅读原文与字段、查看定位、添加产品行、修正／确认字段、记录人工审核时间 |
| 缺失与冲突 | 查看阻塞项和提醒项、来源、英文澄清草稿及供应商询价草稿 |
| 报价 | 录入成本／费用／加价率／汇率／商业条款、查看计算、新建版本、提交／批准／退回、导出 |
| 跟进 | 手动确认发送、创建／完成／延期任务、显示负责人和逾期、更新业务状态 |

| 权限 | 销售 | 主管 |
| --- | --- | --- |
| 读取本组织询价、原文件、报价和任务 | 是 | 是 |
| 创建询价、修正字段、编辑报价与提交 | 是 | 否 |
| 批准或退回待审批报价 | 否 | 是 |
| 导出符合条件的报价、确认已发送、操作任务 | 是 | 是 |
| 访问其他组织资源 | 否 | 否 |

角色和组织均由后端会话确定。修改请求中的组织 ID、隐藏按钮或猜测资源 ID 不得改变权限。会话之外的附件链接也必须鉴权。演示账号限定显式启用的本地演示环境。

## 导入和来源

支持粘贴邮件正文、`.eml`、文本型 `.pdf`、`.xlsx`。每次保留原始文件／正文、导入时间、所属组织、文件状态和处理记录。多产品、多型号、多数量保持行级关系，不得合成一个产品。

对损坏文件、超限、类型不支持、无文本 PDF 和模型失败分别说明原因。可保留原文并转人工时不丢失已接收材料；被拒绝的文件必须说明未接收。手工补录和重试入口应可见。重复导入返回已有询价并提示，不能重复创建询价或跟进。重试需保护人工修改和版本历史。

| 字段范围 | 字段 |
| --- | --- |
| 询价级 | 客户、联系人、目标交期、目的地、Incoterms、付款条件、币种、有效期 |
| 产品行级 | 产品名称、型号、数量、单位、材质、尺寸、技术参数 |

每个提取字段保存原始值、规范化值、原文摘录、文档 ID、定位、提取方法、待核实原因、人工确认值、修改人和修改时间。定位使用邮件行／段、PDF 页码、Excel 工作表与单元格。人工补录明确标为人工，不补造来源。模型提供的来源要与原文对应；无法定位或相互不一致时保留待核实标记，不作为可信概率。

人工修正立即持久化，刷新与服务重启后保留。原文作为证据保存，不被修正值覆盖。合成演示标记随询价持续展示。

## 检查规则

保存草稿始终允许缺失信息。审批检查和算价检查分别在后端执行。

报价工作区提供“暂存未完成报价”：成本、汇率或条款不完整时，已填写部分仍可存入数据库，刷新后继续。暂存不执行算价，不产生可审批金额；修改报价工作草稿会使旧审批失效。信息补齐后通过“计算并保存新版本”生成确定的报价快照。

| 级别 | 例子 | 行为 |
| --- | --- | --- |
| 阻止审批 | 数量／单位未确认、必要规格缺失或冲突、来源冲突未处理 | 保留草稿，给出字段与来源，处理后才能审批 |
| 阻止计算 | 缺失成本、非法或非正数量、非正汇率、非法费用／加价率、币种不明确 | 不给出看似有效的金额；零成本只能由人明确填写 |
| 提醒 | 未提供客户期望交期、目的地或付款条件；相对日期无锚点；独立产品行中重复型号 | 允许整理草稿，商业条款中的未知项显示待确认；重复型号由人对照来源核实 |
| 不适用 | 当前品类不使用的规格 | 由人记录不适用原因，不凭空补值 |

相同型号不同数量、单位不一致、邮件与附件冲突要保留各自来源。人工选择一个值不能抹去冲突历史。英文澄清邮件仅列已知事实与问题；供应商询价仅生成草稿。

当前品类要求客户名称，以及产品名称、型号、数量、单位、材质和尺寸。所有非空提取字段都需人工确认。未提供的可选字段保留空白提示；规格确实不适用时人工填写“不适用：具体理由”并确认，保留修改审计。MVP 尚无独立的品类规则管理页面。

## 报价规则

所有金额由十进制代码计算，模型不参与算价。成本、费用、汇率、加价率和条款由销售明确输入。

```text
成本合计 = Σ(数量 × 单位成本) + 运费 + 其他费用
销售金额（成本币种） = 成本合计 × (1 + 加价率)
销售金额（报价币种） = 销售金额（成本币种） ÷ 汇率
汇率 = 1 单位报价币种对应的成本币种数量
毛利率 = (销售金额（成本币种） - 成本合计) ÷ 销售金额（成本币种）
```

验收例：100 件 × CNY 20 + 运费 CNY 200、其他费用 0，加价率 25%，汇率 7.2 CNY/USD，总额 USD 381.94，毛利率 20%。未录入税费不得自动追加。加价率不等于毛利率。数量和单位成本输入最多 6 位小数，加价率／汇率最多 8 位，货币金额显示 2 位。Decimal 使用 ROUND_HALF_UP；各产品销售金额、运费销售金额和其他费用销售金额分别舍入，总计按总成本加价换汇后舍入，两者差额以 `roundingAdjustment` 独立列示，确保行合计等于总额。费用不分摊进产品行。

明确填写的零成本可以参与计算；若总成本与销售金额均为零，毛利率显示“不适用”。报价有效期按 Asia/Shanghai 的当地日期判断，到期当天仍有效。

报价版本保存由服务端填写的客户抬头、产品与规格快照、成本规则、结果、交期、付款、Incoterms、有效期及完整邮件主题／正文。后续修订客户名称不改变旧版抬头。内部版本为内部草稿。正式客户导出要求当前获批版本，且来源修订号仍匹配。导出写审计记录。

自动生成的英文邮件在下一次报价金额或条款变化时重新生成；前端带回未改动的上一版自动稿不会固定旧金额。用户明确修改的邮件保留人工文本，由主管对照新版本核实。每个已保存版本的邮件内容保持原样。

| 报价状态 | 允许的主要迁移 |
| --- | --- |
| 草稿 `draft` | 销售提交到 `pending` |
| 待审批 `pending` | 主管批准到 `approved` 或填写原因退回 `returned` |
| 退回 `returned` | 销售修改后创建新版本并重新提交 |
| 已批准 `approved` | 可正式导出及人工确认已发送；影响报价的修改需新版本与重新审批 |
| 已替代 `superseded` | 保留历史证据，不得作为当前正式报价导出 |

审批、导出和确认发送均再次校验组织、角色、版本及前置条件。旧版本可追溯，不能继承审批、修改已批准快照或通过直接状态修改绕过审批。

## 跟进和时间记录

询价状态：新询价、等客户补充、等供应商、待审批、已报价、跟进中、赢单、丢单、暂停。批准和导出不等于已发送。只有用户明确确认已发送后才记录发送时间、更新到已报价并创建一次报价后的跟进任务。重复确认返回已有任务。

任务保存所属询价、关联报价、负责人、到期时间、待办／完成状态和完成时间。延期保留操作审计，逾期由到期时间与未完成状态判定。提醒先在应用中展示。

应用记录审核时间、字段修改和任务完成时间。审核时间是用户记录的审核片段，并非覆盖导入、沟通、报价及批准的完整工时。试点另用 [效率记录模板](pilot-measurements.csv) 记录端到端人工操作时间与外部等待。

## 数据和验收原则

Organization／User／Customer／RFQ／RFQItem／SourceDocument／ExtractedField／QuoteVersion／QuoteItem／Approval／DraftMessage／FollowUpTask／AuditEvent／ProcessingJob 的概念可合并存储，但组织、来源、版本和审计关联不能丢失。报价和草稿可使用版本快照存储。

至少 10 组合成样本覆盖正常与异常流程。支持格式真实读取原文；无 Key 时规则或手工提取仍可处理任意输入，不把任意文件映射成固定样本结果。真实 Provider 接口和配置存在不代表真实请求已验证。

完成要求：构建、类型检查、核心风险测试、浏览器完整流程、刷新及重启持久化均有实际结果；不得用截图或测试代码本身证明通过。独立风险场景见 [REVIEW_CHECKLIST.md](REVIEW_CHECKLIST.md)，真实客户验证见 [PILOT_KIT.md](PILOT_KIT.md)。
