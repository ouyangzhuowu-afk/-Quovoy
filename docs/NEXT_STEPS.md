# 最少后续行动

本文件列出本地技术验收后的外部验证步骤。真实模型、真实客户、生产部署和付款均需独立证据；当前状态以 [ACCEPTANCE.md](ACCEPTANCE.md) 为准。

| 顺序 | 负责人 | 最少输入／动作 | 完成证据 |
| --- | --- | --- | --- |
| 1 | 项目负责人 | 按 README 在本地启动，复演一份完整询价；确认 ACCEPTANCE 中的剩余项 | 实际版本、命令、页面与持久化结果；未过项保留具体原因 |
| 2 | 业务负责人 | 找到一家适合的企业、一名销售与一名主管，选定一个零部件品类 | 试点联系人、字段规则与决策人明确 |
| 3 | 客户与项目负责人 | 确认可使用的数据范围，取得少量脱敏邮件／文本 PDF／Excel；冻结真值与基线方式 | 原件清单、许可范围、来源真值与测量口径 |
| 4 | 技术负责人 | 若需真实模型，按 README 配置模型服务、模型名和 Key；先只用获准数据 | 成功和失败请求各一例、来源核对、错误恢复记录；Key 不入库、不入日志 |
| 5 | 双方业务负责人 | 讨论 14 天／≤30 份询价试点和价格假设，明确付款与退出条件 | 约定范围、双方认可的指标、实际付款另留凭证 |
| 6 | 客户操作员与复核人 | 运行试点，保留失败和人工兜底，填写效率表 | 每份配对人工时间、外部等待、字段真值与错误证据 |
| 7 | 双方负责人 | 第 14 天复盘并决定续费、有限补测或停止 | 有分母的结果、限制、预算决定和下一动作 |

## 真实接入路径

真实模型路径通过 `AIProvider` 接入。先验证结构化输出、超时／失败、来源一致性和无凭据时的明确降级，再用真实标注集测试准确率。一次请求成功不能证明模型质量达标。

真实邮件接入保留为后续适配器：接收已授权邮箱或转发服务事件 → 校验来源和组织映射 → 原件持久化 → 以消息 ID／内容摘要去重 → 调用现有导入入口 → 记录处理作业。收件与发送分别授权；MVP 保持人工外发。没有邮箱凭据时，EML 上传是可用入口，不声称邮箱已连接。

## 若要公开部署

先准备可审阅的配置和迁移方案，再由负责人批准生产发布。最少需明确：运行环境和域名、正式用户及密码／会话管理、私有文件存储、持久化数据库、HTTPS、备份恢复、日志保留、模型数据去向和运行责任人。关闭并验证无法启用公开演示账号，确认附件无公开静态路径。

本地 SQLite 单实例不能被当作无状态多副本服务部署。采用持久卷的单实例时须说明备份与恢复；切换 Postgres／对象存储时按 [DECISIONS.md](DECISIONS.md) 重做事务、并发、组织隔离、幂等及附件测试。进程重启后的未完成作业恢复需实际演练。

当前不要求用户提供邮箱密码或生产账户来完成本地 MVP。不应将 Key、账号、客户附件或数据库上传到公开仓库。真实外发、付费资源、公开部署、删除数据和生产迁移必须在明确授权范围内进行。

## 可选功能的进入条件

OCR、工程图理解、供应商报价自动归一化、历史检索、邮箱连接、ERP、统一身份认证、批量导出和固定 PDF 模板依次由真实试点中的重复阻塞决定优先级。先修复已证实的核心流程风险，不能以增加功能替代未完成的必做验收。
